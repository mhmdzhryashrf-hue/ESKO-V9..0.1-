## 1. الهوية وإدارة الإصدارات

- العلامة العامة في المستودع: **ESKO / ESKO JOKER / OPEN HUB**.
- الاسم الذي طلب المستخدم ظهوره للتطبيق حرفيًا: `The new system is ESCO`. توجد كتابة مختلفة بين ESKO وESCO؛ لا تُغيّر نص اسم التطبيق دون اعتماد صاحب المشروع.
- لا يُعتمد رقم إصدار ثابت إلى الأبد. القاعدة المطلوبة: زيادة الجزء الأخير بمقدار `0.0.1` مع كل تحديث أو إضافة معتمدة، مع رفع الجزء الأكبر عند التغيير الرئيسي/الفرعي المتفق عليه.
- يجب أن يكون رقم إصدار الموقع وبيانات التطبيق وصفحة التنزيل وسجل التغييرات وواجهة API متزامنًا. لا يُعلن إصدار منشور لمجرد تغيير النص في الواجهة.
- السجل المرفوع يستهدف `V9.0.2`، لكن المستودع الذي تمت مراجعته يعرض الويب `V3.0` وملف تنزيل Android `V3.2` ونسخة Web Preview باسم `V4.5`. لذلك لا يمكن تأكيد أن `V9.0.2` إصدار فعلي منشور أو أن الإصدار التالي هو `V9.0.3` قبل مطابقة النسخة المثبتة/المنشورة.

## 3. هيكل التنقل الرئيسي المطلوب

يُبنى الموقع حول ستة أقسام رئيسية ثابتة، بأيقونات واضحة مثل تطبيقات التواصل. على الهاتف يمكن عرضها كشريط سفلي، وعلى الشاشات الكبيرة كشريط علوي/جانبي متجاوب:

1. **البيت:** موجز المنشورات، النشر، الإعجابات، التعليقات، المشاركة، البحث، التصفية، التنبيهات. يوضع زر المساعد الذكي أعلى الصفحة.
2. **البوتات:** فهرس البوتات، البحث والتصنيف، إنشاء بوتك، حالة الربط والتشغيل.
3. **المستودعات:** المشاريع والمواقع، استيراد ZIP، ربط GitHub، محرر المشروع، المعاينة والبناء والاختبار والنشر.
4. **المتجر الإلكتروني:** كتالوج المنتجات/الأدوات والموارد الرقمية، التفاصيل والتوافق، الإضافة إلى مكتبة المستخدم والتنزيل.
5. **المساعد:** مساحة الذكاء الاصطناعي الشاملة ومهام البرمجة والتصميم والتحليل والتوثيق والاختبار.
6. **الحساب:** الملف الشخصي، منشورات المستخدم، مكتبته، سجل التنزيلات والمشاريع، الإعدادات، الدعم، الخصوصية والأمان.

تحت الأقسام يظهر عنصر **الكتب — تحت الإنشاء** بخط عريض، ويظل معطلًا أو يعرض حالة «تحت الإنشاء» حتى تجهز بياناته؛ لا يُعرض كقسم يعمل قبل ذلك.

## 4. البيت والمنشورات

- موجز منشورات موحد مع نشر نص وصورة وفيديو، تحرير وحذف المنشور وفق صلاحيات صاحبه، وإبلاغ/إخفاء المحتوى المسيء.
- لكل منشور: إعجاب/إلغاء إعجاب، تعليق/ردود، مشاركة عبر رابط أو أدوات المشاركة، وعدّادات متزامنة من الخادم.
- البحث عن المنشورات والمستخدمين والوسوم، وفرز الموجز وفق أحدث/متابعة/الأكثر تفاعلًا حسب الخيارات المعتمدة.
- عرض حالة الإرسال: مسودة، جارٍ الإرسال، نُشر بعد تأكيد الخادم، أو فشل مع إعادة المحاولة. لا تُعرض رسالة نجاح قبل الاستجابة الفعلية.
- زر المساعد الذكي مثبت أعلى واجهة البيت.
- تصميم النسر المتحرك مخصص للبيت، مع تلاشي/انتقال بصري متصل بمقدمة الفيديو بعد التحقق من ملف الفيديو النهائي. يجب ألا يغطي أزرار التصفح أو النصوص.
- تحتاج المنشورات والتعليقات والإعجابات والمشاركة إلى API وقاعدة بيانات ومصادقة ومكافحة إساءة استخدام؛ لا يكفي تخزينها في `localStorage`.

## 5. قسم البوتات وميزة «أنشئ بوتك»

يوفر القسم فهرس القوالب الحالية، ويضيف منشئ بوت مخصصًا بالاسم المطلوب **أنشئ بوتك**.

### نموذج إنشاء البوت

- الحقل 1: اسم البوت.
- الحقل 2: وصف البوت ووظيفته.
- قائمة أوامر قابلة للإضافة: لكل أمر حقل **اسم الأمر** وحقل **وصف ما يجب تنفيذه**.
- زر «إضافة أمر» يسمح بإضافة الصفوف حتى حد أقصى 100 أمر للبوت الواحد.
- زر ثابت أسفل النموذج: **إنشاء البوت**.
- عند الضغط، يحول المساعد الوصف والأوامر إلى خطة، ثم يولد ملفات البوت وبنيته واختباراته، ويعرض معاينة وفروق الملفات قبل الحفظ.
- يحدد المستخدم منصة التشغيل (مثل Telegram أو Discord أو Web/API) قبل البناء؛ لا يُدعى أن البوت متصل أو منشور حتى تجهز بيانات الاعتماد والـ adapter وتنجح اختبارات الاتصال.
- كل أمر يحتاج تعريفًا للمدخلات والمخرجات والصلاحيات والأخطاء المتوقعة، مع منع التنفيذ الحر غير المحدود.
- حفظ الإصدارات وسجل أوامر البوت ونسخة احتياطية، وإتاحة تعديل/تعطيل/حذف البوت وفق الصلاحيات.

**خط الأساس الحالي:** يوجد 50 قالب بوت في امتداد V5، ويظهر تنبيه داخل المصدر أن تشغيل القوالب على Telegram/Discord/خدمات أخرى يحتاج إعداد المنصة ومفاتيحها؛ لم يظهر نموذج إنشاء بوت يضم 100 أمر.

## 6. المستودعات ومركز المطور

- إنشاء مشروع موقع أو تطبيق من وصف نصي، أو من قالب، أو من ملف ZIP بعد الفحص.
- ربط المستودع بحساب GitHub لصاحب المشروع، مع اختيار المستودع والفرع والصلاحيات بعد موافقته.
- قراءة بنية الملفات وتحليل الاعتماديات واكتشاف الملفات الناقصة والتعارضات، ثم تقديم خريطة مشروع.
- محرر الملفات يعرض الفروق قبل تطبيق أي تعديل، ونقاط استعادة قبل عمليات التغيير.
- أدوات البناء والاختبار والتوثيق والتصدير يجب أن تعمل عبر Worker معزول عند الحاجة، لا داخل صفحة GitHub Pages.
- دعم معاينة Staging قبل النشر، ثم نشر بعد اجتياز الاختبارات وموافقة المستخدم.
- تنفيذ أوامر Termux الحالية في الموقع يتم عبر نسخ الأمر فقط. لا تتحول أزرار النسخ إلى تنفيذ مباشر دون بيئة واضحة وموافقة وصلاحيات.

### اختصار المعالجات `789`

يُعامل `789` كاسم/اختصار وظيفي لمساحة المعالجات، وفق السجل المرفوع: 20 معالجًا جديدًا، ثم 10 إضافية؛ أي 30 وحدة معالجة/أداة ذكية على الأقل. لا يعني ذلك إضافة 30 نواة CPU. لكل وحدة اسم ووصف ومدخلات ومخرجات وصلاحيات واختبار وسجل تشغيل. يجب ألا تكون مجرد بطاقة شكلية.

## 7. المتجر الإلكتروني وكتالوج الأدوات

- المطلوب إضافة **300 أداة** إلى المتجر. حتى يتضح خلاف ذلك، يُستخدم في المواصفات هدف مبدئي هو كتالوج يضم 300 عنصر متميز على الأقل، مع سجل قابل للزيادة؛ لا تُحتسب أوامر Termux أو بطاقات قوالب البوتات تلقائيًا كمنتجات متجر.
- كل عنصر له اسم ووصف وصورة/أيقونة وفئة ونسخة وتوافق وسعر/مجانية ومصدر ورخصة وبصمة تحقق وحالة توفر.
- زر «إضافة» يضيف العنصر إلى مكتبة المستخدم، ثم يستطيع التطبيق والموقع قراءة المكتبة نفسها من API موحد. التنزيل والتثبيت خطوتان منفصلتان؛ لا تثبيت صامت.
- مزامنة قائمة المتجر ومكتبة المستخدم بين الموقع والتطبيق، وإظهار آخر وقت مزامنة ومعالجة حالات انقطاع الشبكة.
- لوحة إدارة لإضافة/تعديل/إيقاف عنصر، ومراجعة سلامة الإضافات والتقييمات والرخص.
- خط الأساس الحالي يحتوي مصادر خارجية للتنزيل وروابط APK قديمة ومكتبة أوامر Termux (200 عنصر)، وليس متجرًا إلكترونيًا بكتالوج موحد وطلبات شراء/تنزيل مرتبطة بالحساب.

## 8. المساعد والذكاء الاصطناعي

- واجهة عربية افتراضية تدعم تحليل الطلب وتحويله إلى خطة وخطوات قابلة للمراجعة.
- مساعد كتابة الأكواد وتصحيحها وشرحها، تحليل المشروع والملفات، توليد واجهات، اختبارات، توثيق، قواعد بيانات وواجهات API.
- وكلاء تخصصيون (تخطيط، تصميم، برمجة، اختبار، أمان، توثيق، نشر) مع مدير مهام وذاكرة مرتبطة بالمشروع.
- يعرض المساعد الملفات المتأثرة والفرق والمخاطر ونتائج الاختبار؛ لا يطبق تعديلًا مؤثرًا أو ينشر من غير موافقة صريحة.
- يجب تحديد موفر النموذج أو الخادم ومفاتيح API في الخادم فقط، مع قياس الاستخدام وحدود التكلفة. لا تُحفظ مفاتيح الذكاء الاصطناعي داخل JavaScript العام أو المتصفح.
- لا تعرض استجابات قواعد ثابتة على أنها ذكاء اصطناعي توليدي. في المستودع، مساعد `app/v4.5` المحلي حاليًا يعتمد قواعد/مطابقات نصية ويصف نفسه بأنه ليس نموذجًا توليديًا.

## 9. الحساب والإعدادات والدعم

- ملف شخصي قابل للتعديل وصورة مستخدم، منشورات المستخدم، سجل النشاط والمشاريع ومكتبة المتجر.
- أيقونة الدعم وأيقونة الإعدادات في أعلى منطقة الحساب.
- إعدادات اللغة والثيم وسرعة الحركة وتقليل الحركة والصوت والخصوصية والإشعارات وإدارة الجلسات.
- دعم تسجيل الدخول/إنشاء الحساب واسترجاع الحساب من خادم آمن فقط؛ القفل المحلي لا يُعد حسابًا سحابيًا.
- صلاحيات وأدوار للمستخدمين والفرق، وحماية البيانات وإمكانية تصديرها وحذفها وفق السياسة.

## 10. اللغات والصوت والحركة والفيديو

- العربية هي اللغة الافتراضية والأساسية.
- دعم 45 لغة في واجهة الموقع والتطبيق، مع ملفات ترجمة منظمة ومراجعة نصوص RTL وLTR. يجب اختبار عرض الأرقام والتواريخ والنماذج وأسماء الملفات.
- أصوات للتفاعل والتنبيه والنجاح والخطأ مع كتم منفصل ومستوى صوت قابل للضبط وبدائل مرئية.
- خلفية متحركة مختلفة لكل قسم من الأقسام الستة، مع خيار تقليل الحركة احترامًا لإعداد الجهاز وأداء الهاتف.
- مقدمة الفيديو تظهر أولًا ثم تلاشي إلى البيت؛ خيار التخطي، وعدم إعادة تشغيلها عند كل تنقل داخل الأقسام.
- المتاح في المستودع فيديو واحد `media/esko-intro.mp4` بحجم 5,555,431 بايت؛ لا يمكن اختيار «الأكبر من فيديوهين» حتى يتم توفير الفيديو الثاني أو الإشارة إلى مكانه.
- لا يُحوّل الفيديو إلى Base64 داخل HTML. يحفظ كملف أصل مستقل مضغوط، مع صورة Poster، وقياس زمن التحميل واستهلاك الذاكرة. ربط النسر بالفيديو يكون انتقالًا بصريًا (fade/overlay) لا تشغيلًا متوازيًا ثقيلًا.

## 11. النشر من Termux وGitHub

التدفق المطلوب في الواجهة:

1. إدخال اسم مستخدم GitHub واسم المستودع والفرع.
2. إدخال Token داخل مطالبة آمنة، لا داخل حقل عام يُحفظ في المتصفح.
3. التحقق من أن الرمز يملك الحد الأدنى من صلاحيات المستودع المقصود.
4. عرض الملفات التي ستُرفع والفرق ورسالة Commit والفرع المستهدف.
5. اختبار/بناء ثم طلب تأكيد المستخدم قبل الرفع أو الدمج.
6. متابعة حالة النشر وإظهار رابط الموقع وسجل الأخطاء بعد تأكيد GitHub.

**حماية الرمز:** لا يُرسل Token إلى ChatGPT أو يُكتب في ملف JavaScript أو `config.js` أو مستودع عام أو سجل أو لقطة شاشة. يُستخدم من جلسة Termux/خادم موثوق مع أقل صلاحيات لازمة، ويُلغى إذا انكشف. لا يُسمح بمتابعة النشر إذا فشل الاختبار أو غابت الموافقة.

**الحالة الحالية:** كود Termux الموجود يعرض أوامر تعليمية قابلة للنسخ فقط. المستودع منشور عبر GitHub Pages وفق README، ولم يظهر سير نشر CI/CD أو معالج نشر Token متكامل في شجرة `main` التي فُحصت.

## 12. الأمن والخصوصية

- لا يمكن جعل ملف عام قابل للتنزيل «غير قابل للتعديل أو الاستخدام» بمجرد تشفيره؛ يستطيع من يملك الملف نسخه أو تعديله محليًا. الحماية الواقعية تكون بتوقيع الحزم، والتحقق من البصمات، وحفظ الأسرار على الخادم، وتفعيل الصلاحيات والترخيص، وعدم توزيع أسرار داخل الملفات.
- حماية مفاتيح GitHub وAPI في الخادم/مخزن أسرار، وإلغاء صلاحياتها عند الحاجة.
- تشغيل أدوات البناء وتحليل ZIP في بيئات معزولة مع حدود ملفات وشبكة وموارد.
- فحص الملفات المستوردة من ZIP ضد traversal والملفات التنفيذية الخبيثة والحجم المفرط قبل فكها.
- فصل بيانات المستخدمين والمشاريع، وتسجيل عمليات التغيير والنشر والمراجعة.
- لا تُستخدم بيانات المستخدمين أو تسجيلات الشاشة في تدريب النماذج دون موافقة وسياسة معلنة.

## 13. خريطة المتطلبات العابرة للموقع والتطبيق

تُنفذ ميزات السجل 33–315 بحسب ملاءمتها للويب: مولد Android والمواقع، محرك الكود، كشف الأخطاء، التصميم من الصور وFigma، قواعد البيانات وAPI، إدارة GitHub، الاختبارات والنشر والنسخ الاحتياطي، التوثيق، المتاجر والقوالب والألعاب، التحليلات، CI/CD، الأمان، الترجمة وإمكانية الوصول، وكلاء الذكاء الاصطناعي، ذاكرة المشروع، مقارنة الإصدارات، بيئات المعاينة، النشر التدريجي، PROJECT RESCUE، PROJECT CONSCIOUSNESS، وSELF-EVOLUTION. لا تُعد هذه البنود منفذة حتى يكون لها خدمة فعلية واختبار قبول.

## 14. معمارية التنفيذ المقترحة

- **واجهة الويب:** HTML/CSS/JS أو إطار متفق عليه، متجاوبة، مع فصل العرض عن خدمات API.
- **الخلفية:** API HTTPS للمصادقة والمنشورات والتعليقات والمتجر والمكتبة والمشاريع والعمليات، مع قاعدة بيانات دائمة.
- **عامل المهام:** صف Jobs لبناء المشاريع واختبارها وتحليل ZIP وتشغيل وكلاء الذكاء الاصطناعي داخل Sandbox.
- **تكامل GitHub:** OAuth أو GitHub App/Token محدود الصلاحية، مع موافقة لكل مستودع/فرع.
- **تخزين الأصول:** ملفات الفيديو والصور والحزم على تخزين مناسب مع CDN/Cache وبصمات تحقق.
- **واجهة مشتركة للتطبيق والموقع:** تعريف API ومخططات بيانات موحدة للمتجر والحساب والمنشورات والمشاريع والإصدارات.
- GitHub Pages يمكنه تقديم واجهة ثابتة، لكنه لا يوفر وحده قواعد بيانات وحسابات مشتركة وطوابير بناء أو نماذج AI خاصة؛ يلزم Backend مستقل لهذه الوظائف.

## 15. اختبارات قبول الموقع

- فتح أول مرة: مقدمة الفيديو تنتهي أو تُتخطى ثم يُعرض البيت، مع خيار تثبيت/تحميل التطبيق.
- كل واحدة من الأيقونات الست تفتح القسم الصحيح على الهاتف والحاسوب، وتُحفظ حالة التنقل عند الحاجة.
- اختبار نشر منشور، تعديل/حذف حسب الصلاحية، إعجاب، إلغاء إعجاب، تعليق، مشاركة، وبحث على حسابين تجريبيين بعد ربط Backend.
- اختبار منشئ البوت: إضافة 1 و100 أمر، رفض 101، حفظ، توليد، عرض فروق، اختبار؛ وإثبات فشل/نجاح adapter المنصة.
- اختبار استيراد ZIP وتحليل بنية المشروع دون تنفيذ أي ملف مستورد تلقائيًا.
- اختبار إضافة منتج إلى المكتبة من الموقع وظهوره في التطبيق بعد المزامنة.
- اختبار دعم 45 لغة وRTL/LTR وقراءة عناصر الواجهة بواسطة تقنيات الوصول.
- اختبار نشر GitHub باستخدام Token اختبار محدود، والتحقق من عدم ظهوره في المصدر أو السجلات.
- اختبار البطء وانقطاع الشبكة والأجهزة محدودة الذاكرة، وإيقاف الحركة والصوت.
- لا يُقبل الإصدار إذا فشل اختبار حرج أو ظهر رابط/زر لا ينفذ وظيفته المعلنة.

## 16. العوائق والأخطاء المؤكدة وقت المراجعة

1. التنقل الفعلي للموقع لا يزال خمسة تبويبات فرعية، وليس ستة أقسام.
2. العلامات والإصدارات غير متناسقة: V3.0 للموقع، V3.2 لملف APK، V4.5 للمعاينة، V9.0.2 لسجل المواصفات.
3. الموجود 200 أداة في ملف بيانات Termux؛ المطلوب 300 أداة في المتجر، وهما نوعان مختلفان.
4. لا يوجد Backend ظاهر في المستودع؛ الواجهات التي تحتاج مزامنة أو حسابًا سحابيًا لا يمكن اعتمادها حاليًا.
5. لم يظهر متجر إلكتروني موحد أو موجز اجتماعي حقيقي.
6. يوجد 50 قالب بوت، لكن لا يظهر نموذج «أنشئ بوتك» حتى 100 أمر.
7. أصول الفيديو الظاهرة في المستودع ملف واحد؛ لا يوجد فيديو ثانٍ للمقارنة.
8. واجهة الموقع تستخدم بعض معالجات `onclick` المضمنة؛ ينبغي مراجعتها عند تفعيل سياسة CSP صارمة.
9. توجد مواضع تستخدم `innerHTML` في وحدات الأدوات/الامتداد؛ يجب إكمال مراجعة escaping للبيانات المتغيرة قبل استقبال مدخلات عامة أو بيانات خادم غير موثوقة.
10. لم يتم تشغيل بناء أو اختبار End-to-End أو اختبار تحميل أو تدقيق اختراق ديناميكي في هذه الجلسة.

## 17. حالة التنفيذ

**المنجز في هذه المراجعة:** فحص شجرة مستودع GitHub وملفات الويب الأساسية وملفات بيانات الأدوات وملفات الامتداد وملف مواصفات التطبيق المرفوع؛ إنشاء هذه الوثيقة بوصفها فصلًا لمواصفات الموقع.

**غير المنجز:** تعديل الموقع، إنشاء Backend، كتابة 100 أداة إضافية أو 300 منتج، إنشاء بوت حقيقي، إعداد مفاتيح GitHub، بناء نسخة تطبيق، تحسين الفيديو، إنشاء النسر المتحرك، أو نشر إصدار جديد.
