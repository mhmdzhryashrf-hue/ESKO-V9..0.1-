# دمج حماية Android الأصلية — ESKO V5.6

هذه الحزمة تعدّل ملفات الويب في `docs` فقط؛ لا تحتوي مشروع Android أو ملفات APK. النقاط التالية متطلبات دمج للكود الأصلي قبل إعلان أن التطبيق محمي بالكامل.

## شبكة وWebView

- اجعل الاتصالات HTTPS فقط، وعطّل cleartext traffic في Manifest وNetwork Security Config.
- عند استخدام WebView، اسمح بنطاق ESKO الرسمي فقط في التنقل؛ افتح الروابط الخارجية في المتصفح بعد التحقق من المخطط والمضيف.
- عطّل `allowFileAccess` و`allowContentAccess` وMixed Content ما لم توجد حاجة موثقة ومراجعة.
- فعّل Safe Browsing، ولا تفعّل JavaScript إلا لأن وظائف التطبيق تحتاجه.
- لا تعرض JavaScript bridge عامًّا لكل الصفحات أو النطاقات. اسمح بعمليات محددة قليلة، وتحقق من مصدر الاستدعاء والبيانات.
- لا تسمح للصفحات الخارجية باستدعاء واجهات Android الأصلية.

## مفاتيح وملفات

- استخدم Android Keystore لإنشاء مفاتيح التشفير داخل التطبيق الأصلي، مع AES-GCM ومفتاح منفصل لكل غرض عند الحاجة.
- لا تخزن مفاتيح التشفير أو كلمات المرور في SharedPreferences أو ملفات نصية.
- لا تعِد استخدام IV مع المفتاح نفسه. احفظ بيانات الخوارزمية والـ IV مع الملف المشفر، ولا تحفظ المفتاح معه.
- اجعل الملفات الحساسة ضمن مساحة التطبيق الخاصة، وراجع النسخ الاحتياطية ومشاركة الملفات عبر ContentProvider.
- تشفير صفحة الويب للملفات لا يستبدل حماية Android Keystore ولا يشفر قاعدة بيانات التطبيق تلقائيًا.

## هوية وإشعارات

- نفّذ تسجيل الدخول والتحقق من الجلسات على خادم HTTPS؛ لا تعتمد على قفل واجهة أو PIN ثابت داخل APK.
- لا تحفظ كلمات المرور أو رموز جلسة طويلة الأجل في SharedPreferences أو WebView localStorage.
- استخدم واجهة إشعارات Android/FCM من الخادم، واحفظ مفاتيح الخدمة على الخادم فقط.
- أعد التحقق من الهوية قبل الإجراءات الحساسة، وادعم تسجيل الخروج وإبطال الجلسات.

## شرط الإصدار

لا تعلن اكتمال الحماية قبل بناء APK من مصدر Android، وفحص إعدادات Manifest وWebView وKeystore والإشعارات على جهاز تجريبي، وإجراء مراجعة أمان للخادم. هذه التعديلات غير موجودة في Patch الويب الحالي.
