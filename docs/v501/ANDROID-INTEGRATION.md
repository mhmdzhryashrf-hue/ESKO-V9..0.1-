# دمج V4.5 داخل تطبيق Android الأصلي

هذا الدليل يحدد نقاط الدمج المطلوبة، ولا يدّعي أن التطبيق الأصلي عُدّل بالفعل.

## الملفات المطلوبة للدمج الحقيقي

نحتاج المصدر الفعلي لـ V3.2، وخاصة:

- `MainActivity.java` أو `MainActivity.kt`.
- `AndroidManifest.xml`.
- Gradle files وإعداد WebView الحالي.
- أصول HTML/CSS/JS الموجودة داخل `app/src/main/assets/`.
- ملفات الأيقونة والألوان وموارد الثيمات.

الحزمة السابقة `ESKO-V3.2-SOURCE-REVIEW.zip` لم تُرفع بعد؛ الملف المتاح سابقًا كان سكريبت تجهيز المصادر فقط.

## نقاط الدمج

1. دمج واجهة V4.5 في أصل WebView الحالي مع المحافظة على مسارات JavaScript bridge الموجودة وعدم حذف أي دوال قديمة.
2. توصيل قفل الدخول بـ Android Keystore ومفتاح تشفير محلي. يجب ألا يُخزّن PIN أو كلمة المرور كنص أو كـ hash ثابت داخل assets.
3. إعداد إظهار لوحة المفاتيح ومعالجة الرجوع ودورة حياة Activity حتى لا تضيع حالة الإدخال.
4. فتح Termux الأصلي بتكامل Android موثق بعد معرفة طريقة تثبيته/حزمة التطبيق وإعداداته؛ لا تنفّذ نصوص shell عشوائية مستلمة من الويب.
5. اختبار التخزين والترقية مع بقاء بيانات الإصدار السابق؛ أي تغيير في قاعدة البيانات يحتاج migration لا حذفًا.
6. مراجعة صلاحيات Manifest قبل إضافتها. لا تُطلب صلاحية كاميرا/موقع/ميكروفون لمجرد وجود واجهة لها.

## بوابة قبول قبل إصدار APK

- بناء Release باستخدام إعدادات Gradle/SDK الحالية دون تغيير أدوات SDK عشوائيًا.
- `aapt dump badging` للتأكد من package/version/minSdk/targetSdk.
- `zipalign -c -v 4`.
- توقيع بنفس شهادة ESKO السابقة، والتحقق من V2/V3 ومن بصمة الشهادة قبل توزيع تحديث.
- تثبيت فوق النسخة القديمة على جهاز اختبار والتحقق من بقاء البيانات.
- اختبار رفض كلمة المرور الخاطئة، وحدود محاولات الدخول، وإعادة تشغيل التطبيق، وفقدان/استرجاع الجهاز.
