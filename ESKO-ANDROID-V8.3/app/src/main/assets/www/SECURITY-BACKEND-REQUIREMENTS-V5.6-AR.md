# متطلبات خادم الحماية وتسجيل الدخول — ESKO V5.6

## الوضع الحالي

موقع ESKO هنا واجهة ثابتة تستهدف GitHub Pages. ملفات الواجهة لا تستطيع وحدها حفظ حسابات آمنة أو إنشاء جلسات HttpOnly أو ضبط ترويسات HTTP أو مراقبة الخادم وقاعدة البيانات. لذلك يعرض مركز الحماية ما يمكن للمتصفح قياسه فقط، ويضع حالة الخادم على أنها غير مكتملة حتى يوفّر API متوافقًا.

## متطلبات تسجيل الدخول قبل استقبال حسابات حقيقية

1. كلمات المرور تُخزن كـ Argon2id مع salt عشوائي وفريد لكل حساب، لا كنص واضح ولا كتشفير قابل للفك. إعداد OWASP الحالي الأدنى يتضمن 19 MiB ومرورين ودرجة توازٍ 1؛ يجب ضبط القيم وقياسها على الخادم الفعلي. عند تعذر Argon2id يُستخدم بديل موصى به من OWASP بعد مراجعة الإعدادات.
2. الجلسة تُنشأ وتُدار على الخادم، ويكون معرّفها عشوائيًا وقابلًا للإبطال والتدوير بعد تسجيل الدخول أو تغيير الصلاحيات.
3. كوكي الجلسة تحمل Secure وHttpOnly وSameSite=Strict أو Lax حسب تدفق الدخول، ولا تُخزن رموز الجلسة أو refresh tokens في localStorage أو sessionStorage.
4. جميع عمليات التغيير تتحقق من CSRF، مع فحص Origin/Referer عند اللزوم. لا يُعتبر SameSite بديلًا عن CSRF.
5. تحديد محاولات الدخول وإعادة الاسترجاع على الخادم حسب الحساب وعنوان الشبكة، مع تأخير تدريجي ورسائل عامة لا تكشف وجود اسم المستخدم.
6. التحقق من قوة كلمة المرور على الخادم أيضًا، وإبطال الجلسات بعد استرجاع الحساب أو تغيير كلمة المرور. يُخزن رمز الاسترجاع كهاش ويُقبل مرة واحدة ثم يُبدل.
7. دعم MFA أو Passkeys/WebAuthn قبل منح صلاحيات حساسة. لا توضع أسرار TOTP أو مفاتيح التوقيع في ملفات JavaScript.
8. استخدام استعلامات قاعدة بيانات معلّمة، والتحقق من كل صلاحية في كل endpoint، وتسجيل أحداث الدخول الحساسة دون حفظ كلمات مرور أو رموز جلسات.
9. إتاحة HTTPS فقط، مع نسخ احتياطي مشفر وخطة استعادة وتحديثات أمنية للخادم.

## مسارات API المقترحة

- `GET /api/security/health`: يعيد حالة محمية غير حساسة؛ يستخدم مركز الحماية فقط لعرض ما يعلنه الخادم.
- `POST /api/account/register`, `POST /api/account/login`, `POST /api/account/logout`, `POST /api/account/recover`: المسارات التي تستعملها الواجهة حاليًا، وتحتاج تنفيذ الضوابط السابقة.
- `POST /api/notifications/subscribe`: حفظ PushSubscription بعد موافقة المستخدم.
- `POST /api/security/csp-report`: استقبال تقارير CSP بعد تفعيل report-to/report-uri في إعدادات الاستضافة.
- `POST /api/security/ai-review`: اختياري، ويستقبل قائمة مؤشرات منقحة لا مفاتيح أو كلمات مرور أو ملفات خاصة.

شكل الصحة الاختياري الذي تتوقعه الواجهة:

```json
{
  "auth": {
    "ready": true,
    "passwordHash": "argon2id",
    "secureCookies": true,
    "rateLimit": true,
    "csrf": true
  }
}
```

هذه القيم تصريح من الخادم وليست تدقيقًا مستقلًا؛ يجب اختبارها فعليًا.

## مراقبة الثغرات والمساعد الآلي

- مركز الواجهة يراقب أخطاء JavaScript ورفض الوعود ومخالفات CSP وحالة الشبكة.
- المراجعة السلبية تقرأ ترويسات استجابة الصفحة وملفات JavaScript من نفس المصدر فقط، ولا تنفذ استغلالًا ولا تفحص منافذ أو أجهزة زوار.
- المحلل المحلي يعتمد قواعد ثابتة لتحديد أنماط خطرة وتقديم توصيات. لا يوجد نموذج توليدي مربوط افتراضيًا.
- إصلاح الترويسات أو أخطاء الخادم يتم من ملفات إعداد الخادم أو مصدره، وليس من JavaScript داخل الصفحة. لا تسمح للمساعد بتطبيق تغييرات عمياء على الإنتاج؛ أنشئ patch ثم اختبره وراجعه قبل النشر.
- فعّل مراقبة سجلات الخادم، تنبيهات فشل الدخول، نسخ قاعدة البيانات، ومراجعة تحديثات الحزم في بيئة الخادم. هذه القدرات لا تظهر تلقائيًا على GitHub Pages.

## ترويسات HTTP

اضبطها على مضيف الموقع/الوكيل العكسي، ثم اختبرها مع وظائف البحث الخارجية قبل فرض CSP. كحد أدنى راجع:

- `Content-Security-Policy` مع `default-src`, `object-src 'none'`, `base-uri 'self'`, و`frame-ancestors`.
- `Strict-Transport-Security` بعد التأكد من HTTPS على النطاق.
- `X-Content-Type-Options: nosniff`.
- `Referrer-Policy: strict-origin-when-cross-origin` أو سياسة أشد.
- `Permissions-Policy` لتعطيل صلاحيات الكاميرا والميكروفون والموقع غير اللازمة.

GitHub Pages لا يسمح بتشغيل ملف backend من مجلد `docs` ولا يعني وجود ملف إعداد في المستودع أن هذه الترويسات قد فُرضت. اتبع طريقة مزود الاستضافة أو الوكيل العكسي الفعلي.

## Push Notifications

ملف Service Worker يدعم استقبال حدث Push، لكن الإشعارات البعيدة لا تعمل دون مفتاح VAPID عام في `window.ESKO_VAPID_PUBLIC_KEY`، وخادم يحفظ الاشتراكات ويرسل الرسائل باستخدام المفتاح الخاص على الخادم. المفتاح الخاص لا يوضع في الموقع أو التطبيق. إشعار الاختبار المحلي لا يحتاج خادم إرسال.
